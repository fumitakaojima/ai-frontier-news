# AI最前線新聞 — Editorial UI Design Brief v1.4

決定日: 2026-11-09〜10
ステータス: **合意済み・実装未完**。現行の公開サイトは創刊号の基本UIであり、この完成デザインではない。

## プロダクト体験
- 最初の瞬間に「新聞だ」と認識できる。テクノロジーメディア風のカードUIやアプリ風のランディングページにはしない。
- 記事への最初の接触で「AIって、そんなことまでできるの？」という**知る感動・知的好奇心**を届ける。
- AI初心者に学習を強制しない。ニュースで接触→興味→自発的な学習→体験という心理段階を支援する。
- 新聞はニュースを知る楽しさが中心。将来の雑誌・特集・体験ガイドは**アイデア段階であり実装決定ではない**。

## ビジュアルの原則
- 優先順位は A: 伝統的な紙の新聞 > C: Web向け操作性。B: いわゆる派手なテクノロジーメディアの方向性は採用しない。
- 新聞の題字、号数、日付、横罫線・細い縦罫線、見出しのメリハリ、複数の段組を一面に採用。
- ファーストビューは「巨大なロゴだけ＋広い空白」ではなく、**題字とその号の一面見出しが同時に見え始める**配置。
- 紙の新聞に寄せつつ、文章は画面で読める大きさ、スマートフォンでは段組を安全に縦積みする。
- 見出し・要約・発表日・出典・記事種別は明確に区別する。
- 主役は原則として**記事の見出し**。そのニュースで実際に説明価値がある画像・図解が得られた場合はビジュアル主役に切り替える。ニュースと無関係な装飾画像を大きく置いてスペースを埋めない。

## 見出しの編集
- 見出しは読者の**好奇心や「自分には何ができるようになる？」**という想像を引き出す。
- 補足見出し・リードで**何が発表されたか**を一次情報に忠実に説明。煽り、誇大な断定、事実を隠すクリックベイトは禁止。
- A: 知的好奇心 / B: 自分ごと感 は媒体や読者を固定分類せず、ニュースと読み手の状況に応じて使い分ける。
- 目を引く大見出しは実際のニュースに基づく。ニュースのない日には無理に記事を水増ししない。

## 画面の具体的な受け入れ条件
1. PC初期表示: 新聞題字・年月日・号数・一面の大見出しをスクロールせず認識できる。
2. PC初期表示: 複数記事が新聞のコラムとして視覚的に並ぶ。1〜3記事しかない場合でも不自然な空白を大きく作らない。
3. 一面見出しは一般記事より明確に大きい。横罫線と段差で重要度がわかる。
4. 一面の画像は本物のニュースを伝える図版・写真だけに限定し、権利・出典・代替テキストを確認する。画像がなければ画像なしの新聞風紙面を選ぶ。
5. 幅375px〜PC幅1440pxで横スクロールしない。スマホでは少なくとも題字・号数・一面見出しが読める。
6. 記事詳細: **30秒で理解する / なぜ重要か / 技術を深掘り / 一次情報と留意点**が確認できる。
7. ニュース、専門家の解説、実践事例は別の分類。個人見解を公式発表として表示しない。
8. 色は新聞紙を連想させる落ち着いた地色と文字色を主体とし、色数を絞る。
9. 日付別バックナンバーと関連記事の移動はわかりやすくする。
10. 自動発行で異なる記事数・見出し長・画像有無にも対応。データ不足の場合はデザインを壊さず、誤ったニュースも作らない。

## 模倣基準の確定（2026-11-10）
- **The Wall Street Journal（WSJ）の紙面構成**を正式なデザイン参考とする。模倣するのは記事の優先順位、段組、罫線、題字と日付の扱いなどの一般的な編集レイアウトの考え方であり、ロゴ・独自フォント・紙面デザインの厳密な複製はしない。
- **横書きを固定**。日本語の縦書き題字や記事本文は採用しない（ユーザー明示決定）。
- **主記事は中央、第二記事は左、第三記事は右**。重要度の違いを主見出し・副見出し・リードのサイズと情報量で表現する。
- いわゆるLPの巨大なタイトル表示や巨大な一面見出しだけでファーストビューを埋めない。PCでは題字・号数・三記事の見出しが同時に見えること。
- 新聞らしさは紙面の編集構造で表現し、派手な写真や装飾で水増ししない。画像は一次情報や権利を確認でき、記事を理解する価値があるときにのみ配置する。
- スマホでは**中央の主記事→左の第二記事→右の第三記事**の順に自然な1列にする。
- 3件未満の記事数でも破綻しない1列・2列のレイアウトを用意する。
- 見出しは読者の好奇心を引く一方、原典の事実に忠実であること。
- 現在のPR #4はこの決定事項を反映した候補。**本番mainへのマージはユーザーが実画面をレビューするまで禁止**。

### 前回案からの変更
縦書き日本語新聞案と、巨大な横書き1面見出し案は不採用。横書きWSJ型の主記事＋左右の短報を正式な基準とする。

## 2026-11-10 追加決定：ビジュアルを主役にした読みやすい紙面
- ユーザーは横書きWSJ型の初稿を「文字文字しい」と評価。**直感的に話題が伝わる写真・説明グラフィック・イメージ画像**を記事に配置する方針を追加。
- 中央の最重要記事には大きなビジュアル、左右の2記事にも固有のビジュアルを使い、**記事の絵・見出し・要約**の順で読み進められる。
- 画像を置くために架空のニュースや無関係な写真を追加しない。
- 初号の暫定ビジュアルは編集部が作成したSVG概念図3点。製品画面・独立検証・実際の生成画像と誤解されないよう、適切なaltと「イメージ図」のキャプションを必ず表示。
- 数字入りの説明グラフィックは元発表の数値・比較対象を確認して掲載し、発表元の公表値と第三者評価を区別する。
- 将来実写写真・公式製品画像を使う際は、画像元の権利・利用条件・出典・altを確認する。無断複製はしない。
- 画像未収集の日は画像を無理に捏造せず、ニュースに合う安全な代替レイアウトにする。

## 2026-11-12 実装更新
- 最新の明示決定を優先し、画像→見出し→要約の順に興味を引くビジュアル主導の一面へ更新。中央の大きなCGと左右の記事固有画像を同時に表示する。
- 暫定SVGからオリジナルAI生成CG/写真風の利用イメージ3点へ変更。実物・公式画面と区別するキャプションを常時表示。

- モバイルは主記事→左記事→右記事。新しい定期課金、生成API、外部画像配信は追加しない。
- 制作条件・プロンプト・ファイル・事実との対応は VISUAL_ASSETS.md に記録。
