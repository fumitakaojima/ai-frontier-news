# AI最前線新聞 — Editorial UI Design Brief v1.4

決定日: 2026-11-09〜10
ステータス: **合意済み・実装未完**。現行の公開サイトは創刊号の基本UIであり、この完成デザインではない。

## プロダクト体験
- 最初の瞬間に「新聞だ」と認識できる。テクノロジーメディア風のカードUIやアプリ風のランディングページにはしない。
- 記事への最初の接触で「AIって、そんなことまでできるの？」という**知る感動・知的好奇心**を届ける。
- AI初心者に学習を強制しない。ニュースで接触→興味→自発的な学習→体験という心理段階を支援する。
- 新聞はニュースを知る楽しさが中心。将来の雑誌・特集・体験ガイドは**アイデア段階であり実装決定ではない**。

## ビジュアルの原則
- 優先順位は A: 伝統的な紙の新聞 > C: Web向け操作性。B: いわゆる派手なテクノロジーメディアの方向性は採用しない。
- 新聞の題字、号数、日付、横罫線・細い縦罫線、見出しのメリハリ、複数の段組を一面に採用。
- ファーストビューは「巨大なロゴだけ＋広い空白」ではなく、**題字とその号の一面見出しが同時に見え始める**配置。
- 紙の新聞に寄せつつ、文章は画面で読める大きさ、スマートフォンでは段組を安全に縦積みする。
- 見出し・要約・発表日・出典・記事種別は明確に区別する。
- 主役は原則として**記事の見出し**。そのニュースで実際に説明価値がある画像・図解が得られた場合はビジュアル主役に切り替える。ニュースと無関係な装飾画像を大きく置いてスペースを埋めない。

## 見出しの編集
- 見出しは読者の**好奇心や「自分には何ができるようになる？」**という想像を引き出す。
- 補足見出し・リードで**何が発表されたか**を一次情報に忠実に説明。煽り、誇大な断定、事実を隠すクリックベイトは禁止。
- A: 知的好奇心 / B: 自分ごと感 は媒体や読者を固定分類せず、ニュースと読み手の状況に応じて使い分ける。
- 目を引く大見出しは実際のニュースに基づく。ニュースのない日には無理に記事を水増ししない。

## 画面の具体的な受け入れ条件
1. PC初期表示: 新聞題字・年月日・号数・一面の大見出しをスクロールせず認識できる。
2. PC初期表示: 複数記事が新聞のコラムとして視覚的に並ぶ。1〜3記事しかない場合でも不自然な空白を大きく作らない。
3. 一面見出しは一般記事より明確に大きい。横罫線と段差で重要度がわかる。
4. 一面の画像は本物のニュースを伝える図版・写真だけに限定し、権利・出典・代替テキストを確認する。画像がなければ画像なしの新聞風紙面を選ぶ。
5. 幅375px〜PC幅1440pxで横スクロールしない。スマホでは少なくとも題字・号数・一面見出しが読める。
6. 記事詳細: **30秒で理解する / なぜ重要か / 技術を深掘り / 一次情報と留意点**が確認できる。
7. ニュース、専門家の解説、実践事例は別の分類。個人見解を公式発表として表示しない。
8. 色は新聞紙を連想させる落ち着いた地色と文字色を主体とし、色数を絞る。
9. 日付別バックナンバーと関連記事の移動はわかりやすくする。
10. 自動発行で異なる記事数・見出し長・画像有無にも対応。データ不足の場合はデザインを壊さず、誤ったニュースも作らない。

## 現行v1とのギャップ（2026-11-10時点）
- 実装済: 大きな日本語題字、日付、号数、区切り罫線、1件のヒーローと記事リンク、記事詳細の二層構造、バックナンバー。
- 未実装: 新聞的なコラム段組、初期表示の圧縮、一面の可変型、意味ある画像のみに限定する切替、新聞としての情報密度、複数端末での詳細な検証。
- 現行の `.hero-art` は「AI Frontier.」という汎用的な装飾。記事固有の情報がないため、これを無条件に主役として表示しないよう改善する。
